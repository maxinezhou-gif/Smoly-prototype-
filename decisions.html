Design decisions

Everything in the Smolify-a-book prototype that is not simply read off Smoly App Design §781:26595 and the Smoly Material Library. Three kinds of entry: calls made while building, places the Figma file disagrees with itself or with the prototype, and conventions that any production implementation will hit too.

Decided while building

Not in the Figma file. Treat these as proposals — each one is a line or two to change.

Decided here

The tile is always seen before the sheet

Every entry point adds the tile, lets it dissolve in and centre itself, waits 800ms, then opens the sheet. On Record next audio the open sheet slides out first and the delay starts after it has cleared, so the new tile is never introduced behind a panel.

Decided here

A new tile scrolls to the middle, not the bottom

It is the thing the user just made, so it should be what they are looking at when the sheet arrives.

Decided here

The bulk pair is always present once a list exists

Not gated on how much has been recorded. What changes is the secondary button: it counts the recordings still waiting for a sticker and goes disabled when there are none.

The primary stays live in every state — recording is how you get out of an empty list, so disabling it would be a dead end.

Confirmed

The count is unlinked recordings, not all recordings

A recording that already has a sticker is finished, so counting it in “Link n stickers” would overstate the work left. Confirmed by design: already-linked recordings are not counted.

Confirmed

The timer counts up to the cap, not down from it

20:00 is the ceiling for a single recording, and the timer runs up towards it — mm:ss / 20:00. The cap itself is a placeholder until the dev team confirms the real storage limit; see Open — for the dev team below.

Decided here

Changing the cover opens a menu, not the OS picker

Change photo raises a menu with Photo library, Take a photo and Choose file. iOS offers those same three from one native sheet, so the design is drawing explicitly what the OS would otherwise decide — worth knowing, because a production build gets the native sheet free from a single file input and would have to opt out of it to match this.

All three land on the same picker. Take a photo adds capture so a phone opens the camera rather than the gallery. Picking an image swaps the cover for real, so the prototype demos with the right book.

Decided here

One tile expanded at a time

Expanding another tile, collapsing, deleting or re-recording all stop playback. Two players running at once is never what anyone wants. Tiles still on No audio do not expand, since there is nothing to play.

Decided here

The status bar is covered, not scrolled away

The Figma structure lets it scroll off entirely. Here it sticks at top: 0 and the contents frame paints over it, so it is buried on the way down and uncovered on the way back — the bar itself never moves. A toggle on the index decides whether it is drawn at all, defaulting off on a phone, which already has a real one.

Decided here

Additions with no Figma source

The scrim behind the sheet, the toast used for out-of-flow actions, and the halo that pulses around the dial while recording. The halo exists in one build only — smolify-book.html has it, smolify-book-flat.html does not.

Where the Figma file disagrees

Found while building. Each one is a decision someone has to make in the file, not in code.

Figma conflict

Two timer formats

The Front Page sheet reads 00:00:27 / 00:20:00; the Recording - #1 sheets read 00:27 / 20:00. The prototype uses mm:ss / 20:00.

Figma conflict

The Home nav icon

The file specifies on-secondary-container #00458f for it, which reads as an active destination while you are in the Create flow. The prototype uses on-surface-variant as directed. File and prototype now differ.

Figma conflict

The bulk-action state has no frame

Described but never drawn. Composed from the Medium button at the same 56 / 16 rhythm as the pair inside the sheet.

Figma conflict

Body/Small is no longer used, and the frames grew

Every Body/Small usage moved to Body/Medium for legibility on a phone. The 16 → 20 line-height moves geometry the frames still show at the old size.

Conventions for implementation

Each of these was a real bug in this prototype before it was a rule. A production build will meet all of them.

Convention

A Figma stroke is not a CSS border

Figma draws strokes inside the box. On an element whose height comes from its content, a 1px border adds 2px — the audio tile measured 54 / 138 where the design says 52 / 136. Use an inset ring instead: box-shadow: inset 0 0 0 1px …. Elements with an explicit height are unaffected.

Convention

A sticky offset must track whatever sits above it

Sticky pins an element as soon as its natural position is above the threshold. Leaving the app bar at top: 62px with no status bar above it pushed the bar 62px down the page, and the contents frame then covered it.

Convention

Leading space is padding on the parent, not margin on the child

A top margin on a first child collapses out of its parent and drags the whole frame down. The 4px above the book cover did exactly that, opening a band of device background under the arch that looked like a rendering seam.

Convention

No font shorthand for component type

A CSS-wide keyword is only valid as an entire property value, so font: 600 14px/20px inherit is invalid and the whole declaration is dropped silently — every button label fell back to the browser default of 13.33px/400. The shorthand also resets font-family. Use longhands.

Convention

Entrance animations clean up after themselves

Remove the class on animationend, with a timer as backstop. Leaving it on means the element leans on animation-fill-mode forever and parks at its starting keyframe — blurred and at 97% — if the animation never runs, which happens in a backgrounded tab.

Convention

Token exceptions worth knowing

Filled buttons take --smoly-color-button-on-filled #ffffff, not on-primary. XSmall and Small buttons use Label/Large; Medium uses Title/Medium. The Add text button’s label is on-primary-container #8f043f, not primary — not a value anyone would guess from a render.

Open — for the dev team

Design questions are answered. These need an engineering answer before the behaviour can be finalised.

Needs an answer

What is the storage cap for one audio tile?

The 20:00 ceiling in the prototype is a placeholder, not a decision. What is the real limit for a single recording — and is it bounded by device storage, by what the wand can hold, or by an upload size?

Current behaviour: recording stops silently on reaching 20:00. That is a placeholder too — silently stopping mid-sentence is not something anyone chose.

Once confirmed, one of two things happens: the cap is lifted entirely if there is no meaningful limit, or it stays and gains a toast when the user reaches it, so the stop is explained rather than just happening. Both are small changes — MAX_SECONDS at the top of app.js plus a few lines in stopRecording.

Being designed elsewhere

Separate flow

Link to a sticker

Its own flow, in design now, to be built into this prototype afterwards. Both entry points exist and are wired — the button inside the sheet and the bulk action under the list — and currently raise a toast instead of navigating.
